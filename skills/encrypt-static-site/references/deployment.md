# Browser verification and deployment

## Verify a specific project

Use a temporary localhost server rooted **only** at the generated output and
mounted at the configured base path. A plain file:// URL does not work. For a
subpath build, the server must actually mount at that path; adding the prefix to a
root-only server's URL does not do this automatically.

Exercise the real app in an isolated browser context:

- Wrong passphrase: show exactly `Wrong password`, restore the enabled Unlock
  button, and allow a correct-password retry without reloading. No protected DOM
  or successful asset response should appear.
- Downloading: show progress separately from password checking. A stalled download
  must time out visibly and allow retry; network failures must not be labelled as
  a wrong password.
- Correct passphrase: expected HTML, CSS, fonts, binary images and local JSON.
- ES module imports and a user action that loads a dynamic chunk.
- Direct nested URL before unlocking, internal navigation, reload and browser back.
- For React: state updates/hydration and actual router routes, not only a screenshot.
- For Next.js: Link navigation/prefetch, nested pages, client components, exported
  data fetches and refresh; inspect page errors and failed requests.
- Worker stopped/restarted: navigation asks for the password again. Explain that
  lazy requests from already open pages may fail until reload.
- A separate browser context starts locked; lock-all removes access in site tabs.
- Public server responses contain no original assets. Use server logs or an
  independent HTTP client: DevTools inside an unlocked tab shows decrypted responses
  served by the Service Worker, so readable content there is expected.
- CacheStorage, IndexedDB and browser storage contain no engine-written keys or
  plaintext. Any app-written storage is separate and must be disclosed.

Run `verify` again after any generated-file change. Do not add source maps, preview
screenshots, debugging dumps, reports, source files or a manifest of original names
to the upload. The expected public file list is generated by `publicFiles()`.
Host-side settings are applied outside the verified output unless the engine
explicitly generates them. Avoid CDN/host transformations of runtime JavaScript.

## Static hosts

Publish the contents of the generated folder at the chosen base. The public root
contains `index.html`, a generic `404.html`, `sw.js`, `_sealed/` (ciphertext and
runtime), crawler/host directives and `.nojekyll`. Never upload the original
`dist`, `out`, project root, or the skill repository as the protected site.

| Host | Setup |
| --- | --- |
| GitHub Pages, project URL | Build app and encrypt with `/repository/`. Upload only the generated artifact or its contents to a dedicated publishing repository/branch. `.nojekyll` preserves underscore files. Generic `404.html` bootstraps direct nested URLs; the first request can retain HTTP 404 until the worker controls navigation. Pages does not offer this folder's custom `_headers` rules. |
| GitHub Pages, custom domain/user root | Build and encrypt with `/`. Configure the domain in the host settings, outside the verified artifact. |
| Netlify / Cloudflare Pages | Deploy the generated folder. `_headers` adds noindex/no-store headers. The generic `404.html` bootstraps unknown paths; the initial response is 404 until the worker controls navigation. Normally use base `/`. No catch-all `_redirects` rule is emitted: Cloudflare applies rules even when a real runtime asset exists. |
| S3 + CDN / conventional static server | Use HTTPS, set JS MIME types correctly, disable caching of the shell, worker and bundle, add equivalent X-Robots-Tag headers, and serve the generic shell for unknown navigation paths while preserving real `_sealed/` files. Configure a slash redirect for the mount root when needed. |

On every host, test the actual published URL, JS MIME types, scope, nested routes
and caching. Local tests do not prove provider-specific configuration. Serving
`sw.js` as HTML prevents registration. HTTP outside localhost is unsupported.
For upgrades, deploy the complete new folder atomically when possible; mixed
versions fail closed and ask the user to reload. Existing unlocked tabs may keep
the prior decrypted version until their worker is replaced or locked.

The public shells and every packaged HTML page have a robots meta tag with
`noindex, nofollow, noarchive, nosnippet, noimageindex`. Check this tag in the
unlocked page source as well as the locked page; original source files are not edited.
`robots.txt` allows fetching so compliant crawlers can see the noindex tag; robots
disallow alone can leave URLs indexed. These are requests to crawlers, not access
control, cache erasure or a promise of URL secrecy.
